# Adal AI

ИИ-помощник по официальным документам на русском и казахском языках.

## Railway

Сайт: https://adal-ai-production.up.railway.app/ · Админка: https://adal-ai-production.up.railway.app/admin

Dockerfile собирает React и запускает FastAPI в одном сервисе. Каталог `/data` подключён
к постоянному Railway Volume: настройки и история в `/data/runtime`, документы в `/data/library`.
Healthcheck: `/health`. Повторная публикация из корня проекта: `railway up --service adal-ai`.

Секреты задаются через Railway Variables, не входят в Docker-образ и клиентскую сборку.
`PUBLIC_WEB_ENABLED=true` открывает браузерный чат; `ADMIN_API_KEY` защищает управление,
`BACKEND_API_KEY` — прямой API. Ключ администратора этой установки сохранён локально
в исключённом из Git файле `.railway-secrets/ADMIN_API_KEY`.

На сайте включены `WEB_CHAT_MODE=deepseek` и `WEB_SEARCH_ENABLED=true`. Перед ответом на
фактический вопрос DeepSeek формирует короткий поисковый запрос, сервер ищет страницы
и загружает до четырёх официальных источников Казахстана. Поиск использует публичный RSS
Bing без дополнительного ключа; доступность выдачи не гарантирована. Для «Адал азамат»
есть резервные адреса Минпросвещения и Правительства, содержимое которых также загружается
из сети при запросе. Поиск получает тему вопроса, а не историю диалога.

Модель отвечает по полученным текстам и указывает номера источников; сервер проверяет
номера и сам создаёт ссылки. Региональные отчёты не должны выдаваться за общенациональные
требования. Если источники не загрузились, бот сообщает об этом, не выдумывая содержание.
Это ответы с веб-источниками, а не сертифицированная проверка Google. Нужны только
`DEEPSEEK_API_KEY` и `DEEPSEEK_MODEL`; ключи и пользовательские диалоги не публикуются.
При `WEB_SEARCH_ENABLED=false` остаётся обычный чат с пометкой об отсутствии проверки.

`WEB_CHAT_MODE=verified` включает строгую проверку по документам. Для неё необходимы
Google Cloud Check Grounding с серверными credentials и проверенные активные документы.
Прямой `/api/ask` и его `/ready` по-прежнему относятся к строгому режиму.
Публикация не активирует документы автоматически.

## Локальный запуск сайта и backend

```bash
./run-local.sh
```

Скрипт собирает frontend и запускает FastAPI, который обслуживает весь проект:

- Сайт: http://127.0.0.1:8000/
- Управление ИИ и документами: http://127.0.0.1:8000/admin
- Контракт API: http://127.0.0.1:8000/docs

Нужны Node.js 22.12+ и npm, а также окружение `backend/.venv` из инструкции ниже.
На этой машине скрипт может использовать встроенный Node.js приложения вместо старого системного.
Остановка — Ctrl+C. Если сервер уже запущен на порту 8000, сначала остановите его.

Фронтенд из архива находится в `frontend/adal-ai/frontend`. Русская и казахская локализации
подключены; выбранный язык передаётся backend. В обычном запуске используются настоящие API,
без тестовых ответов. Ключи и активированные документы нужны для получения ответов ИИ.

История текущего браузера хранится в `backend/data/runtime/chat.sqlite3`, идентификатор —
в HttpOnly-cookie. Хранятся до 100 успешных ходов на диалог; срок сессии — 7 дней,
просроченные записи очищаются при следующем обращении к сессиям. «Новый диалог» создаёт
отдельный чат, предыдущие доступны в боковой истории. «Удалить мои данные» удаляет все
диалоги и сессию этого браузера. Ошибочные ответы не сохраняются.
Список и создание диалогов доступны через `GET/POST /api/conversations`, история выбранного
чата — `GET /api/history?conversation_id=...`; отправка принимает `conversation_id`.
История пока служит для отображения: каждый вопрос ИИ обрабатывает отдельно, без контекста прошлых ходов.

Для разработки с горячей перезагрузкой запустите backend и отдельно `npm run dev` из
`frontend/adal-ai/frontend`: сайт на http://localhost:5173 проксирует `/api` на порт 8000.
Если задан `BACKEND_API_KEY`, передайте его серверу Vite через `ADAL_BACKEND_API_KEY`;
он не попадает в браузерную сборку. Публичное размещение требует отдельной настройки доступа.
Mock включается только явно: `ADAL_MOCK_API=1 npm run dev`.

В каталоге [backend](backend/README.md) находится сервис FastAPI: поиск по подготовленным
документам, генерация DeepSeek/Gemini, проверка цитат кодом, Google Check Grounding и модель-критик.

Страница управления живёт в backend: `http://127.0.0.1:8000/admin`. В ней можно сохранить ключи,
загрузить документы, просмотреть официальные источники и проверить текстовый или голосовой вопрос.
Встроенный каталог содержит 37 официальных источников; загрузка: `python -m app.collector` из `backend`.

Инструкция по запуску и подключению фронтенда: [backend/README.md](backend/README.md).
Подготовка официальных источников: [backend/data/README.md](backend/data/README.md).

Для живых ответов нужны проверенный корпус и доступы к внешним API. Автотесты работают без ключей;
вымышленные тестовые материалы не загружаются в рабочую базу.
