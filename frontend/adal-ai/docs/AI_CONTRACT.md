# Контракт между приложением и ИИ-модулем

> Статус: **предложение приложения**. Документ разделяет то, что уже согласовано,
> и то, что приложение предлагает. Предложенная часть требует подтверждения
> ответственного за ИИ-часть.
>
> Тематика определена положением конкурса «Адал қоғам», п. 4.1: консультант и
> справочник-навигатор по внутренней политике и идеологической работе Казахстана,
> на казахском и русском языках. Требования собраны в
> [COMPETITION_REQUIREMENTS.md](COMPETITION_REQUIREMENTS.md). Приложение ИИ-логику
> не реализует: содержание ответов и база знаний — зона ИИ-части.

## 1. Что подтверждено

Единственная договорённость:

> «Я верну функцию `ask(message, history)`, которая возвращает `answer` и `sources`».

**Не** подтверждены: язык, синхронность, точные типы `history` и `sources`, способ
сообщать об ошибках, время ответа и нужные модулю переменные окружения.

## 2. Что предлагает приложение

### 2.1 Вызов

```python
result = ask(message, history)
```

`message: str` — текущий вопрос пользователя: без пробелов по краям, не пустой,
не длиннее `MAX_MESSAGE_CHARS`.

`history: list[dict]` — **предыдущие** сообщения разговора в хронологическом порядке:

```json
[
  {"role": "user", "content": "Предыдущий вопрос"},
  {"role": "assistant", "content": "Предыдущий ответ"}
]
```

### 2.2 Результат

```json
{
  "answer": "Текст ответа",
  "sources": [
    {"title": "Название источника", "url": "https://example.org/doc"},
    {"title": "Документ без публичного адреса", "url": null}
  ]
}
```

- `answer: str` — непустой текст ответа.
- `sources: list` — может быть пустым. Пустой список ничего не говорит о качестве ответа:
  он бывает у приветствия, уточняющего вопроса и честного отказа.
- `title: str` — название источника для показа пользователю.
- `url: str | null` — публичная ссылка или `null`, если у источника нет публичного адреса.
  У официального документа может не быть публичного URL, и это нормально.

### 2.3 Предлагаемые необязательные поля

Это **предложение**, а не согласованная возможность. Пока ИИ-часть его не подтвердит,
приложение эти поля не требует. Без них интеграция работает по разделу 2.2.

```json
{
  "answer": "…",
  "sources": [
    {"title": "…", "url": null, "details": "Реквизиты или раздел документа — как указано в базе"}
  ],
  "status": "answered"
}
```

`status` — что это за ответ:

| Значение | Смысл | Как показывает приложение |
|---|---|---|
| `answered` | Ответ по найденным материалам | Обычный ответ с источниками |
| `needs_clarification` | Модулю нужно уточнение вопроса | Ответ оформлен как уточняющий вопрос |
| `insufficient_information` | В базе нет подтверждённой информации (п. 4.9 положения) | Отдельная пометка «Нет подтверждённой информации» |

`details` у источника — реквизиты документа (вид, дата, номер) или раздел/статья,
**как они переданы из базы знаний**. Приложение показывает это поле как есть и ничего не дописывает.

Без `status` приложение **не делает выводов** о характере ответа по наличию или
отсутствию `sources`. Ответ показывается как обычный, без пометок «проверено».
Неизвестное значение `status` приравнивается к отсутствию поля, а в лог пишется
предупреждение. Ответ при этом не отбрасывается.

Техническая ошибка (исключение, таймаут, некорректный ответ) — **не** значение `status`.
Она обрабатывается отдельно (раздел 7) и в интерфейсе выглядит иначе, чем
«нет подтверждённой информации».

### 2.4 Язык ответа

Положение (п. 4.6) требует казахский и русский. Сигнатура `ask(message, history)`
при этом не меняется. Предложение по умолчанию:

- модуль отвечает **на языке вопроса** (казахский или русский), определяя его сам;
- переключатель RU / KZ в интерфейсе меняет язык **интерфейса** и сообщений приложения
  (ошибки, подсказки, команды ботов), но не подмешивается в `message` или `history`.

Если модулю нужен явный язык, возможен необязательный именованный параметр
`ask(message, history, *, lang="ru" | "kk")`. Приложение будет передавать его
**только после согласования** и только если функция его принимает.
Внутренний код казахского языка — `kk` (ISO 639-1), в интерфейсе — подпись «KZ».

## 3. Правила, которые гарантирует приложение

1. **`history` не содержит текущий `message`.** Текущий вопрос передаётся ровно один
   раз — аргументом `message`.
2. **`history` формирует сервер.** Она загружается из БД. Браузер и боты передают
   только текст сообщения, поэтому история и системные инструкции от клиента не
   принимаются.
3. **В `history` только роли `user` и `assistant`.** Роль `system` приложение не
   передаёт. Если модулю нужны системные инструкции, он задаёт их сам.
4. **`history` уже обрезана** до `HISTORY_MAX_MESSAGES` сообщений и `HISTORY_MAX_CHARS`
   символов: удаляются самые старые целые пары «вопрос — ответ».
5. **`history` — копия.** Изменения списка внутри модуля не влияют на данные приложения.
6. **Источники прошлых ответов** в `history` не передаются, только `content`.

## 4. Что приложение проверяет в ответе (нормализация)

Фактический формат модуля приводится к формату из раздела 2 **внутри адаптера**
(`backend/app/ai/normalize.py`). Остальной код видит только нормализованный результат.

| Ситуация | Действие |
|---|---|
| `answer` отсутствует, не строка или пустой | Ошибка `AI_BAD_RESPONSE` |
| `sources` отсутствует или `null` | Пустой список |
| `sources` не является списком | Ошибка `AI_BAD_RESPONSE` |
| Источник без `title` или с пустым `title` | Источник отбрасывается, `title` не придумывается |
| `url` не абсолютный `http`/`https` (например `javascript:`, `file:`, относительный путь) | `url` заменяется на `null`, `title` сохраняется |
| `url` длиннее 2048 символов | `url` заменяется на `null` |
| Повторяющиеся источники (одинаковые `title` и `url`) | Остаётся один |
| Слишком много источников / слишком длинный `title` | Обрезка до лимита (предлагается 20 источников, 300 символов) |
| `details` отсутствует, пустой или не строка | Поле не показывается |
| `status` отсутствует или неизвестен | Ответ показывается как обычный, без пометок (раздел 2.3) |

Приложение **никогда** не добавляет источники от себя, не строит URL по названию, не
дописывает номера статей и даты и не загружает URL источников на сервере. Если модуль
не вернул источников, интерфейс просто не показывает блок источников. О том,
достоверен ли ответ, по этому не судят.

Формы результата, которые адаптер примет до уточнения формата:

- `dict` с ключами `answer` и `sources`;
- кортеж `(answer, sources)`;
- объект с атрибутами `.answer` и `.sources` (dataclass, pydantic-модель).

Элемент `sources` — `dict` с ключами `title` и `url` или строка: строка становится
`{"title": строка, "url": null}`. Другие имена ключей (`name`, `link`, `href`…)
добавляются в нормализацию **только после того**, как ответственный за ИИ-часть
подтвердит свой формат. Адаптер не угадывает формат.

## 5. Синхронный и асинхронный вариант

Адаптер поддерживает оба варианта, поэтому для модуля это не ограничение:

- `async def ask(...)` — вызывается через `await` с `asyncio.wait_for(..., AI_TIMEOUT_SECONDS)`;
- `def ask(...)` — выполняется в отдельном потоке (`asyncio.to_thread`) с тем же таймаутом;
- если обычная функция вернула awaitable, адаптер его дожидается.

Ограничение синхронного варианта: по таймауту приложение перестаёт ждать, но
**поток не прерывается** и доработает до конца. Поэтому число одновременных вызовов
ограничено `AI_MAX_CONCURRENCY`. Если модуль поддерживает собственный таймаут для
внешних вызовов (например, к API модели), его стоит включить.

## 6. Способ подключения

| Вариант | Когда | Как |
|---|---|---|
| **A. Python-пакет** (предпочтительно) | Модуль написан на Python | Каталог в репозитории (предлагается `ai_core/`); путь к функции в `AI_MODULE`, например `ai_core.main:ask` |
| **B. HTTP-сервис** | Другой язык или отдельный процесс | `POST {AI_HTTP_URL}` с телом `{"message", "history"}` и ответом в формате раздела 2; токен в `AI_HTTP_TOKEN` (заголовок `Authorization`) |

В обоих вариантах меняется только адаптер. `ChatService` и каналы не меняются.
ИИ-логику приложение не переписывает.

## 7. Ошибки

| Что произошло в модуле | Код в приложении |
|---|---|
| `AI_MODE=real`, а модуль не импортируется | Приложение не стартует (сообщение в логе); `AI_NOT_CONFIGURED` |
| Превышен таймаут | `AI_TIMEOUT` |
| Любое исключение | `AI_FAILED` |
| Ответ не проходит проверку раздела 4 | `AI_BAD_RESPONSE` |

В лог записываются тип исключения и id запроса. Текст сообщения пользователя и
секреты в лог не попадают. Если модулю нужно различать ошибки (например,
«ключ модели не задан», «лимит провайдера»), предлагается выбрасывать отдельные
классы исключений — договоримся о списке.

В режиме `real` приложение **никогда не переключается на mock** при ошибке:
пользователь видит ошибку, а не тестовый ответ mock-режима.

## 8. Режим `AI_MODE=mock`

Используется, пока модуля нет, и в автотестах:

- ответы детерминированы: один и тот же вопрос даёт один и тот же ответ;
- отдельной метки «Демо» в интерфейсе нет (решение команды); текст каждого mock-ответа
  сам сообщает, что это тестовый ответ и ИИ-модуль не подключён;
- mock-ответы **не имитируют** нормативные тексты, цитаты, номера статей и даты:
  это нейтральный текст вида «тестовый ответ, ИИ не подключён»;
- фиксированные тестовые фразы позволяют получить каждый `status` из раздела 2.3,
  чтобы проверить интерфейс до подключения модуля;
- источники либо отсутствуют, либо в названии помечены «не настоящий».
  Для проверки ссылок используется только зарезервированный домен `example.org`;
- фиксированные тестовые фразы вызывают управляемые ошибки (таймаут, некорректный
  ответ), чтобы проверить обработку ошибок без настоящего ИИ.

Тестовые метки в тексте вопроса. Они уже реализованы в dev-mock frontend
(`frontend/dev/mockApi.ts`), и backend MockAdapter должен поддерживать те же:

| Метка | Результат |
|---|---|
| `#clarify` | `status = needs_clarification` |
| `#noinfo` | `status = insufficient_information` |
| `#nostatus` | Ответ без `status` |
| `#sources` | Тестовые источники: со ссылкой на `example.org` и без ссылки, с `details` |
| `#markdown` | Markdown со скриптом, HTML, картинкой и `javascript:`-ссылкой |
| `#error` | `AI_FAILED` |
| `#timeout` | Задержка, затем `AI_TIMEOUT` |
| `#ratelimit` | `RATE_LIMITED` с `retry_after` |
| `#flaky` | Первая попытка `AI_FAILED`, повтор с тем же `client_id` успешен |

## 9. Контрактные тесты

Когда модуль будет передан, адаптер проверяется набором тестов:

- корректный ответ с источниками со ссылками и без них;
- ответ без источников;
- пустой `answer` → `AI_BAD_RESPONSE`;
- `url` вида `javascript:alert(1)` → `url: null`;
- HTML в `answer` отображается как текст;
- исключение в модуле → `AI_FAILED`;
- медленный ответ → `AI_TIMEOUT`;
- `history` не содержит текущий `message`;
- синхронный и асинхронный `ask` дают одинаковый результат;
- без `status` ответ без источников не помечается как «нет информации»;
- неизвестный `status` не ломает ответ.

Содержательная проверка на обоих языках — проверочные диалоги в
[COMPETITION_REQUIREMENTS.md](COMPETITION_REQUIREMENTS.md), раздел 6.
