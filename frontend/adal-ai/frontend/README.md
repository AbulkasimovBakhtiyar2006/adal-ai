# Adal AI — frontend (сайт и PWA)

Интерфейс чата Adal AI: главная страница, диалог, переключатель RU / KZ, источники
под ответами, четыре состояния ответа и установка как PWA.
Архитектура описана в [../docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md).

## Требования

- Node.js 22.12+ (проверено на 24.21.0) и npm.

## Запуск для разработки

```bash
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173.

По умолчанию `/api/*` проксируется на настоящий backend `http://127.0.0.1:8000`.
Запуск всего проекта одним сервером описан в корневом README (`./run-local.sh`).

Только при явном `ADAL_MOCK_API=1 npm run dev` dev-сервер отвечает встроенным **mock API**
([dev/mockApi.ts](dev/mockApi.ts)). Он всегда возвращает `ai_mode: "mock"`, поэтому
отдельной пометки «Демо» в интерфейсе нет, но текст каждого ответа сообщает, что ИИ не
подключён. Mock **не подтверждает** работу ИИ: это тестовые тексты без сведений из базы знаний. В production-сборку он не попадает.

Чтобы работать с настоящим backend, передайте его адрес. Например, в bash:

```bash
ADAL_API_TARGET=http://localhost:8000 npm run dev
```

В PowerShell: `$env:ADAL_API_TARGET="http://localhost:8000"; npm run dev`.

### Тестовые метки mock API

Метку добавляют в текст вопроса, например `Расскажи про закон #clarify`.

| Метка | Что вернёт mock |
|---|---|
| `#clarify` | `status = needs_clarification` |
| `#noinfo` | `status = insufficient_information` |
| `#nostatus` | Ответ без поля `status` |
| `#sources` | Тестовые источники: со ссылкой и без |
| `#markdown` | Markdown со скриптом, HTML, картинкой и `javascript:`-ссылкой для проверки безопасного вывода |
| `#error` | Техническая ошибка `AI_FAILED` |
| `#timeout` | Задержка и `AI_TIMEOUT` |
| `#ratelimit` | `RATE_LIMITED` с `retry_after` |
| `#flaky` | Первая попытка `AI_FAILED`, повтор с тем же `client_id` успешен |

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Dev-сервер с mock API или прокси на `ADAL_API_TARGET` |
| `npm run build` | Проверка типов и production-сборка в `dist/` (с service worker и CSP) |
| `npm run preview` | Запуск собранной версии на http://localhost:4173 с прокси на backend |
| `npm run typecheck` | Проверка TypeScript |
| `npm run lint` | ESLint |
| `npm test` | Тесты Vitest + Testing Library |
| `npm run icons` | Пересоздать иконки PWA из `public/logo.svg` |

## Структура

```
src/
├── api/          # типы API и клиент: нормализация ответа, коды ошибок
├── chat/         # состояние диалога (reducer) и отправка с повтором
├── components/   # шапка, главная, ход диалога, источники, Markdown, поле ввода, диалог подтверждения
├── i18n/         # словари ru.ts и kk.ts, выбор языка
├── App.tsx       # загрузка сессии, уведомления, сборка экрана
└── styles.css    # стили, светлая и тёмная тема, мобильная вёрстка
dev/mockApi.ts    # mock API только для dev/preview-сервера
```

## Правила, которые соблюдает интерфейс

- **Секретов во frontend нет.** Браузер обращается только к `/api/*` своего сервера.
  Сессия хранится в HttpOnly-cookie, переменных `VITE_*` нет.
- **Ответ ИИ — недоверенные данные.** Markdown выводится без HTML, без картинок,
  со ссылками только `http(s)` (`rel="noopener noreferrer nofollow"`).
- **Источники выводятся как есть.** Без `url` ссылки нет, отметки «проверено» нет.
- **Четыре состояния различаются визуально:** ответ, уточнение,
  «недостаточно подтверждённой информации» и техническая ошибка.
  Пока ИИ-модуль не передаёт `status`, ответ показывается как обычный:
  характер ответа по источникам не угадывается.
- **Повтор без дубликата.** У каждого вопроса есть `client_id`, повтор отправляет
  тот же id, а сервер не создаёт второй вопрос.
- **PWA кэширует только статику.** Ответы `/api/*` в кэш service worker не попадают.
- **Казахские тексты** (`src/i18n/kk.ts`) нужно проверить у носителя языка.
